# テンプレートの使い方

次のコードブロックを実際の計画へ転用し、山括弧の記入欄を具体化する。項目は必要な数だけ増減し、IDは既存項目を更新しても維持する。任意の節は必要な場合だけ残す。進捗は冒頭だけに記入し、管理手順を転記しない。完了日は対象作業の完了時にタイトルより後、チェックリストより下へ追加する。

```markdown
# <対象作業の計画>

## 進捗チェックリスト

- [ ] P1 <作業名>
  - 依存先：なし
  - 完了条件：<観測・検証できる条件>
  - 証跡／阻害要因／再開メモ：<未着手なら「なし」。必要になったら記録または詳細へのリンク>
- [ ] P2 <作業名>
  - 依存先：P1
  - 完了条件：<必要な検証も含めた条件>
  - 証跡／阻害要因／再開メモ：なし

## 目的・対象範囲

<達成すること、対象と対象外、現在依頼されている範囲>

## 決定事項・制約

<合意した仕様、許可範囲、維持する制約>

## 設計・調査根拠（任意）

### <論点名>

<必要な根拠・参照。未決なら解決するタスクIDを明記>

## 作業詳細（任意）

### P2の検証

<対象、検証方法、期待結果。実行後は結果と根拠をここへ記録できる>

## 計画全体の完成条件

<対象作業の受け入れ条件と必要な検証。チェックボックスは置かない>
```
